# Certificate provider compatibility

This baseline follows [AutoFirma master at `bd9254be70004be095b1251b5a4af15b9d392dd9`][revision] (19 October 2026) and [Firmica main at `11855fec`][firmica]. The AutoFirma classifications come from source inspection. The Firmica column identifies existing implementation and test coverage. Planned tests and hardware checks are listed separately from evidence already available.

[Store identifiers][enum], [factory dispatch][factory], [key entry handling][manager], and [standalone selection][simple] define the desktop baseline. The built-in desktop defaults are Windows on Windows, Apple Keychain on macOS, and shared NSS on Linux. Standalone settings can override the default. Browser-requested Mozilla selection maps to `MOZ_UNI_WITH_OS`.

## Desktop stores

In the algorithm column, **RSA** means RSA PKCS#1 v1.5 with SHA-256 and a modulus of at least 2048 bits. **P-256** means ECDSA P-256 with SHA-256. These are the Firmica profiles to verify. AutoFirma delegates operations to the selected JCA provider and key, so a factory route alone establishes neither an algorithm guarantee nor hardware support. A platform listed below is a source or planning scope. Driver, runtime and OS combinations must be verified before claiming version support.

| --- | --- | --- | --- | --- |
| `PKCS12` / PFX | Signing capable. User opens a file and selects a private-key entry. | Password-protected software key. AutoFirma uses the JCA PKCS#12 store and supports entry password callbacks. Firmica unlocks one supported identity in its companion worker and supports RSA and P-256. | Desktop Linux, Windows x64, macOS 15+ on Intel or Apple Silicon for Firmica. Linux package compatibility depends on its build distribution. AutoFirma needs a JCA PKCS#12 provider. | Firmica desktop path exists. CI uses synthetic PFX files and covers review, failure, cleanup and signatures. No physical device needed. Multi-entry selection and mobile import are gaps. |
| `WINDOWS` | Aggregate. `CAPIUnifiedKeyStoreManager` combines Current User `MY` through SunMSCAPI with available smart-card managers. | Native key handle or delegated card key. Provider-managed authentication or card PIN. Firmica target is RSA through CSP or CNG, plus P-256 where CNG supports it. | Windows only. AutoFirma needs its Java provider and matching smart-card middleware where applicable. Firmica targets x64 Windows; exact OS/provider floor pending native verification. | Gap. Use temporary Current User certificates for CSP and CNG, including missing key and cancellation. Verify each claimed minidriver or hardware KSP on its device. [Windows manager][capi], [key acquisition][cryptacquire], [CNG signing][ncrypt]. |
| `WINADDRESSBOOK`, `WINCA` | Public certificates. AutoFirma uses `Windows-ADDRESSBOOK` and `Windows-ROOT` respectively through its auxiliary provider. | Certificate enumeration. RSA or P-256 signing only with an accessible matching CSP/KSP key and provider-managed authorization where required. | Windows only. Access depends on store location, permissions, provider and OS version. | Gap. Cover accessible and denied locations and both public-only and usable key entries without elevation. | `APPLE` | Aggregate. Apple `KeychainStore` plus preferred smart-card adapters when available. | Keychain identity or delegated card key. Firmica targets macOS 15+ on both architectures, with token requirements tested per configuration. | Gap. Exercise temporary Keychain identities and permitted/denied signing through Security.framework. Verify each supported token or hardware-backed combination on a device. [Apple manager][apple]. |
| `SHARED_NSS` | Aggregate with a signing-capable internal NSS database and external modules. Verify RSA and P-256 separately. | Linux only in the factory. Requires compatible NSS/NSPR libraries and profile database; external modules need matching architecture and middleware. [Shared NSS discovery][shared]. |
| `MOZ_UNI` | Aggregate. Firefox profile selection and internal NSS plus profile-configured PKCS#11 modules. | NSS-backed software keys and token handles under their module policy. Firefox Primary Password or token PIN when required. Verify RSA and P-256 separately. | Linux, Windows and macOS source paths. NSS/NSPR and readable profile data required. Firefox distribution, OS, architecture and database-version compatibility pending. | Gap. Use disposable profiles to test authorization, isolation and read-only behavior. Physical validation applies to claimed external modules. [Mozilla discovery][mozilla], [unified manager][moz-unified]. |
| `MOZ_UNI_WITH_OS` | Aggregate. Firefox/NSS and external modules plus Windows or macOS native store where applicable. Verify aggregate selection with overlapping names and distinct references. Device evidence comes from the underlying provider. [Combined manager][moz-os]. |
| `PKCS11` | Signing capable. AutoFirma loads a selected native module through SunPKCS11 and can select a slot. | Module-backed software or non-exportable key. Module login/PIN, including per-operation authentication when required. Firmica RSA and P-256 depend on mechanisms, key attributes and policy. | Desktop with compatible module, architecture and vendor runtime. OS/version coverage is per module. | Optional Firmica library backend and disposable SoftHSM tests exist. Desktop discovery, worker isolation and checked cleanup are gaps. Verify both profiles in SoftHSM and check removal, prompts and signing on every physical device claimed. |
| `JAVA` / JKS and `JAVACE` / CaseExactJKS | Signing capable for private-key entries. File selection followed by JCA alias lookup. | `JCEKS` | Signing capable for private-key entries. File and JCA alias selection. | Software private key with store and entry passwords. Firmica target is its desktop package platforms; runtime requirements pending. | Gap. Use JCE fixtures for protection variants, unsupported entries, signatures and cleanup. No physical device needed. [Java dispatch][manager]. |
| `SINGLE` / PKCS#7 or X.509 | Public certificates. AutoFirma file route uses its SingleCert SPI. | No private key, authentication or signing algorithms. | Desktop. No physical device needed. [SingleCert SPI][single]. |
| Encrypted PKCS#8 / PEM | Additional Firmica assessment. No separate store identifier in the pinned factory. | Software key plus matching certificate and password. Assess RSA and P-256 with bounded protection parameters. | Desktop scope pending format and worker assessment. | Gap. Use independent OpenSSL-generated fixtures and deliberate mismatches. No physical device needed. |

## Specialized smart cards

The pinned [AutoFirma dependency file][pom] selects JMulticard 2.1. The [Java driver dispatch][java-card], [preferred adapter registration][preferred-cards] and [known middleware list][known-cards] identify code paths, not a record of successful signing. No physical-card combinations are verified in Firmica at this baseline. For each claim, record the card generation, reader, middleware or driver version, OS and architecture, certificate role, algorithm, and signing result.

| AutoFirma identifier | Classification and discovery | Private-key access and authentication | Platform, prerequisites and verification gaps |
| --- | --- | --- | --- |
| `DNIEJAVA` | Specialized adapter for DNIe and FNMT-TIF. JMulticard `DnieProvider`, also used as a preferred adapter in combined stores. | On-card signing with PIN and card workflow callbacks. Certificate roles differ. Firmica blocks its known DNIe authentication policy and must verify RSA with the document-signing certificate. P-256 requires device evidence. | Desktop with a supported reader, PC/SC and JMulticard for the Java route. Generation and OS coverage pending. Use policy fixtures plus physical DNIe and TIF on every claimed native or middleware path. |
| `CERES` | Specialized adapter for legacy FNMT-RCM CERES via JMulticard `CeresProvider`. | On-card signing with PIN. Verify RSA against the actual card and driver; P-256 requires device evidence. | Desktop with supported reader and PC/SC. Exact generations, OS versions and native replacement path pending. Test a legacy device independently of CERES 4.30. |
| `CERES_430` | Specialized adapter. Factory routes it through configurable JMulticard `DnieProvider` with `allowAnotherCards=true` where available. | On-card signing with smart-card callbacks and PIN. Verify RSA and document-signing certificate selection; P-256 requires device evidence. | Desktop with supported reader and PC/SC. AutoFirma also lists Windows FNMT middleware. Verify CERES 4.30 and later generations individually, including middleware and OS version. |
| `SMARTCAFE` | Specialized adapter for G&D SmartCafe with a PKCS#15 applet via JMulticard `SmartCafeProvider`. | On-card key and PIN. Algorithm and applet coverage pending. | Desktop with reader and PC/SC. Assess supported native middleware or a narrow adapter and verify with a physical card. |
| `KNOWN_SMARTCARDS` | Aggregate used by the Windows manager. The [module list][known-cards] probes FNMT-CERES, Atos CardOS, TUI (UMU/Gemalto) and SafeSign and stops after the first successful card initialization. | Delegates PIN and private-key operations to the loaded PKCS#11 module. Algorithm coverage follows the module and token. | The pinned paths point to Windows vendor libraries. A configured module can use the generic provider where available. Verify each claimed card and middleware version physically. |
| `TEMD` | Unsupported by the pinned factory and base manager. The enum names the Ministry of Defence card with `PKCS11` metadata. | No dedicated key path or algorithm demonstrated by this identifier. | An independently configured module may be viable. Requires documented middleware, supported platform/version and a physical card before any claim. |
| `OTHER` | Unsupported as a standalone factory route. Generic enum value with no provider mapping. | No private-key, authentication or algorithm contract. | No separate Firmica backend planned for this identifier. |

## Mobile targets

The pinned desktop factory has no route for these mobile APIs. These are Firmica targets and do not establish parity findings for AutoFirma's separate mobile clients.

| Target | Discovery, private key and authentication | Platform and prerequisites | Firmica evidence and required verification |
| --- | --- | --- | --- |
| Android system KeyChain | User authorizes a selected alias through `choosePrivateKeyAlias`. Android grants access to a key handle and certificate chain. Verify RSA and P-256 through JCA with supported software and hardware keys. | KeyChain API 14+. Firmica's minimum OS and hardware/provider combinations are pending. [Android KeyChain][android]. | Gap. Verify async alias selection, denial, cancellation and real document signing. A physical device is required for hardware-backed claims. |
| Android application-managed PKCS#12 | Explicit document-provider selection and password-protected import. Software RSA and P-256 are the target. | Android with a compatible PKCS#12 implementation; minimum Firmica OS pending integration. | Gap. Verify imported synthetic identities, separate trust state, output and lifecycle. No physical hardware key needed. |
| iOS application-managed identities | Explicit PKCS#12 import to the app's Keychain, identity lookup and `SecKey` signing. Keychain access controls can require device authorization. Verify RSA and P-256 where available. | iOS Security.framework with appropriate entitlements and access controls. Minimum Firmica OS pending integration. [PKCS#12 import][apple-import], [SecKey signing][apple-sign]. | Gap. Verify actual signatures, output and cancellation. Non-exportable key claims require an accessible matching identity and device evidence. Arbitrary system-wide third-party tokens are outside this route. |
